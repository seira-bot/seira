Local control is off by default. The Electron main process owns the bundled CUA driver lifecycle so operating-system permissions are attributed to Seira rather than a background helper.

## macOS

There is no macOS download. A Seira app that you build on a Mac with `pnpm package:mac` can request Accessibility and Screen Recording permission. After granting either permission, restart the control session when prompted so macOS applies the new grant.

## Ubuntu

On Ubuntu 24.04 with GNOME on Xorg, local control is a beta. Turn on **Enable local control (Beta)** in Settings, wait for **Ready**, then assign a bot to **This computer**. On GNOME Wayland, local control stays off, and Seira clears an older opt-in. To use it, sign out and choose **Ubuntu on Xorg** on the login screen. The Flatpak has no local control. On Xorg and Wayland, chat, screen preview, Cloud, and Local VM work. Do not start the bundled driver manually as a workaround.

## Safety model

- Enabling local control globally does not assign it to a bot.
- Choose **This computer** for each bot that should receive the capability.
- A bot on **Ask for approval** asks before each computer action; at **Full access**, the default, they run without a card.
- Missing permissions, unexpected binaries, unsupported desktop sessions, and failed health checks fail closed.
