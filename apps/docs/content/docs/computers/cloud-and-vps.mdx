## Cloud is your own VPS

A bot's **Cloud** computer is a hardened desktop container on a Linux server you own, reached over SSH. Seira keeps no hosted computer of its own and needs no account for one. If no VPS is set up when you choose **Cloud**, Seira shows one note that links to the setup below, and the bot keeps chatting without a computer.

Every engine with computer tools (Claude, Codex, ACP, Pi, and OpenAI-compatible
connections such as OpenRouter) uses the cloud desktop with the bot's own model
and sign-in in direct chats, groups and routines. For an API connection,
choose a model that supports both images and tools. Screenshots reach that model
at native resolution; tool approvals and **Take control** still apply. A model
without computer tools can't use the cloud computer: choose another model, or set
**Works on** to Auto.

On **Auto**, a conversation works on the VPS only after the bot moves it there
(it asks to switch with `select_computer`), or when it already has a ready container.

Browsers that run in the cloud don't open Reddit: Reddit blocks bots that browse
from cloud computers and can ban the account, so the bot is told to use the
Reddit connected app or ask you to do it on your own computer.

A VPS is your own server, and Seira never powers it off. The bot's managed container can be stopped and started from the Screen panel.

## Bring your own VPS

Follow [Your own VPS (BYO)](/docs/computers/byo-vps) for the setup steps and where to choose Cloud. This keeps the agent on the Seira host; [deploying the whole server](/docs/self-hosting/deploy-vps) is a different setup.

Seira can control Docker on an x86_64 Linux server through an SSH config alias. The agent process stays on your local machine; only Docker commands and the managed desktop container run on the VPS.

Your SSH alias should include connection multiplexing, keepalives, and a connect timeout. Connect manually once to approve the host key, then verify:

```bash
ssh my-vps true
docker -H ssh://my-vps info
```

Install the Docker client on your own computer; the daemon stays on the VPS:

```bash
brew install docker                     # macOS
winget install -e --id Docker.DockerCLI # Windows 10 or 11
sudo apt install docker-ce-cli          # Debian or Ubuntu, Docker's apt repository
```

Windows 10 1809 and later include the OpenSSH client this needs. Podman cannot replace the Docker CLI here: the VPS backend runs `docker -H ssh://<alias>` itself.

The SSH user needs Docker access, which is root-equivalent on that server. Use a dedicated VPS and firewall inbound traffic to SSH only.

The managed container publishes no ports, has no host mounts, and is checked before every attach. Its filesystem should be treated as disposable; move important results out before deleting or upgrading the container.

**Take control** opens the VPS desktop inside Seira through a temporary SSH tunnel. noVNC remains on the container's private bridge network; only a random loopback port is opened on your computer, and the tunnel closes with the viewer.

Auto reuses an already-ready VPS without changing its lifecycle. To let Auto create or wake this bot's managed container, enable **Start VPS automatically** for that bot. This permission is off by default. When neither the VPS nor a local fallback is available, Seira shows the exact VPS failure instead of silently omitting computer tools.
