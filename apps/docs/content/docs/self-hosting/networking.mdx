Seira separates its network surfaces by trust level.

| Surface | Default bind | Purpose |
|---|---|---|
| Harness | `127.0.0.1:8799` (every private address with `serve --lan`) | Full app API and event stream |
| Webhook receiver | `127.0.0.1:8800` | Health and secret hook endpoints only |
| Companion sidecar | `0.0.0.0:8810` when enabled | Paired-device, token-authenticated allowlist |
| Companion control | `127.0.0.1:8811` | Pairing and device administration |

## Remote access

Never forward the harness port yourself. A self-hosted server is reached through one of `seira serve`'s ways in:

- `--public-url https://…`: your own Cloudflare Tunnel, Caddy or nginx in front;
- `--domain HOST`: a managed Caddy that gets the certificate;
- `--tailscale`: your tailnet, with Tailscale's HTTPS when the tailnet has certificates turned on, otherwise plain http on this machine's own tailnet address;
- `--lan`: this network only, plain http. It listens on every address, but answers only connections whose two ends are both private;

Each prints one pairing link; paste it into the desktop app under **＋ → Connect to a server**. The app accepts plain http only on private networks: LAN addresses, Tailscale's 100.64/10 and `*.ts.net`, and `*.local`.

A loopback request counts as the owner only when it really comes from this machine; a LAN client that writes `Host: 127.0.0.1` is still a stranger. For webhook delivery, proxy only the dedicated webhook receiver. Never forward the main harness port to the public internet.

## See which requests reach the server

When you debug a tunnel, a tailnet address or a port, turn on the access log. The server then writes one line for each request it answers, to its normal log:

```sh
npx @seira-bot/seira serve --access-log
# or: SEIRA_ACCESS_LOG=1 npx @seira-bot/seira serve
```

```text
access 2026-11-23T09:15:02.481Z GET /api/health 200 3ms via=local
```

A line holds the time, the method, the route, the status, the duration and the way in: `tunnel` for the phone tunnel, `local` for every other connection. The route is the shape of the path, taken from the list of known routes: a word stays only when no known route reads that position as a name or an id, any other name or id is written as `:id`, and the part of a path that matches no known route is written as `<other>`. It never holds the query string, a cookie, a header or a body. The log is off unless you turn it on.

## Port overrides

Source and advanced deployments can change documented ports with the relevant environment settings. When the default harness port is occupied, packaged builds may fall back to another local port and communicate the selected address internally.
